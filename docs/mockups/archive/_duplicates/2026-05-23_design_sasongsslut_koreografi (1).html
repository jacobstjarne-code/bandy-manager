C-SD1 Säsongsslutets koreografi

Idag finns två oberoende system som båda producerar avslutsskärmar: sceneTriggerService (boolean-kedja för scener) och SeasonPhase + anslagService (för fas-bytena). Inget koordinerar mellan dem. Sommaren glider in före slutspelet, halvvägs-portal + halvvägs-scen säger samma sak i rad, granska-CTA tror serien är klar när den inte är.

Förslag: SeasonEndChoreographer — en explicit state machine som vet säsongsfasen. Scen- och anslags-systemen frågar koreografen "är jag rätt nu?" istället för att gissa.

01STATE-MACHINEsäsongsfaser Sex explicita faser. Varje yta som vill fyra något frågar koreografen vilken fas vi är i. Ingen fas hoppas — övergångar är medvetna.
⬩ Pre-season ⬩
PRE_SEASON
Sommaren-scen avslutad. Anslag: säsongs-kickoff. Söndagsträningen.
enter: nyår-rollover · exit: omg 1 spelad
⬩ Grundserie ⬩
REGULAR_ACTIVE
Cup-final-scener om managed når dit. Kafferum, journalist, signatur — alla aktiva.
enter: omg 1 · exit: omg 22 spelad
⬩ Mellanperiod ⬩
REGULAR_DONE
EN övergångs-skärm: "Grundserien är slut". Inte två. Halvvägs-scen tas bort.
enter: omg 22 klar · exit: playoffBracket skapad
⬩ Slutspel ⬩
PLAYOFF_ACTIVE
PhaseMark "Slutspelet börjar" en gång. RoundMark per omg. SM-finalseger-scen om vinst.
enter: bracket skapad · exit: SM-final klar ELLER managed eliminated
⬩ Spectator ⬩
PLAYOFF_SPECTATOR
SpectatorMark + WatchOthers (om managed elim:ad innan SM). Kafferum tillbaka.
enter: managed elim:ad · exit: SM-final klar
⬩ Säsong klar ⬩
SEASON_DONE
SeasonSummary + ClubMemory-uppdatering. Inget annat utöver det.
enter: SM-final klar · exit: spelaren klickar "Avsluta"
⬩ Sommaren ⬩
SUMMER
Sommaren-scen ("i oktober igen") — får BARA fyra här. Sedan rollover till nästa PRE_SEASON.
enter: spelaren accepterar SEASON_DONE · exit: nyår

03IMPLEMENTATIONarkitektur En ny pure function. Alla scener + anslag frågar den. Inga side-effects, ingen state. Lätt att testa, lätt att utöka.
Ny helper · seasonEndPhase.ts
type SeasonEndPhase = | 'pre_season' | 'regular_active' | 'regular_done' | 'playoff_active' | 'playoff_spectator' | 'season_done' | 'summer' function getSeasonEndPhase(game) { // pure — läser game-state, returnerar fas if (game.inSummerScene) return 'summer' if (game.seasonDoneAck) return 'season_done' if (smFinalCompleted(game)) return 'season_done' if (managedEliminated(game)) return 'playoff_spectator' if (game.playoffBracket) return 'playoff_active' if (regularSeasonDone(game)) return 'regular_done' if (anyMatchPlayed(game)) return 'regular_active' return 'pre_season' }
sceneTriggerService — gateway-pattern
function shouldTriggerSummerScene(game) { if (getSeasonEndPhase(game) !== 'summer') return false // resten av summer-villkoren … } function shouldTriggerHalftimeScene(_game) { return false // tas bort — anslag äger }
anslagService — samma gateway
function shouldShowSummerAnslag(game) { // gateway: bara om koreografen säger summer if (getSeasonEndPhase(game) !== 'summer') return false // resten … }
Nyckelinsikt: alla befintliga trigger-funktioner stannar oförändrade i sin egen logik — de får bara en gateway-check i början. Migrering kan göras inkrementellt (en scen i taget) utan att gå sönder.

Designval öppna till Opus + Jacob

Q1 · "Mellanperiod" — egen skärm eller bara övergång?

När omg 22 är klar men playoff-bracket inte skapad — ska den fasen ha en egen skärm (REGULAR_DONE) eller bara vara övergångsögonblicket mellan grundserie och playoff? Föreslag: egen skärm med ETT anslag ("Grundserien är klar. Slutspelet börjar nästa vecka."). Halvvägs-scen tas bort.

Q2 · Söndagsträningen — egen pre-season-trigger eller hård in i SUMMER?

Söndagsträning fyras idag enbart vid omg 1, första spelet. Med koreografen — flyttas den till SUMMER → PRE_SEASON-övergången så den fyras varje säsong? Föreslag: nej. Söndagsträningen är intro-flödet, en gång hela spelets gång. Behåll one-shot.

Q3 · Spectator-fasen — separat eller alias för playoff_active?

Spec'en i sceneTriggerService skiljer inte mellan "managed i playoff" och "managed elim:ad". Men isManagedClubInPlayoff() finns redan (R3-fix). Föreslag: egen fas. Då kan kafferum/journalist återkomma utan att vänta på att alla playoff-matcher spelas (som idag).

Q4 · SEASON_DONE vs SUMMER — vad triggar övergången?

SEASON_DONE = SM-finalen klar, men spelaren har inte sett summary än. SUMMER = spelaren har klickat "Avsluta säsongen" och summary är visat. Föreslag: spelaren MÅSTE klicka för att gå från SEASON_DONE → SUMMER. SUMMER är medvetet val, inte automatisk.

Implementations-konsekvens

  • Ny fil: src/domain/data/seasonEndPhase.ts (~80 rader pure function)
  • SaveGame-tillägg: seasonDoneAck?: boolean, inSummerScene?: boolean (två booleans för att skilja faserna)
  • Gateway-checks i 5 ställen: shouldTriggerSummerScene, shouldShowSummerAnslag, shouldTriggerHalftimeScene (returnerar false), shouldTriggerSMFinalVictory (gateway: phase är inte spectator/season_done än), playoffIntroScreen-trigger
  • Tester: snapshot av fas per game-state. Lätt — en test per kombination av flags.

Konsekvenser för andra spår

  • R3 PhaseMark: använder redan isManagedClubInPlayoff. Bara byt till getSeasonEndPhase(game) === 'playoff_active'. En linje ändras.
  • Spectator-säsongen: isManagedClubSpectator blir ekvivalent med getSeasonEndPhase(game) === 'playoff_spectator'. Bytas ut, eller behållas som tunn wrapper.
  • C-SP1 granska-CTA: CTA-text fattar beslut baserat på fas. En linje ändras.
  • C-SD2 portal-eskalering: redan löst (R3+ Klimax). Inget extra arbete.

Meta · vad C-SD1 INTE rör

  • Innehåll i scener/anslag — koreografen säger bara "denna fas", inte vad scenen ska säga. Opus copy berörs inte.
  • Cup-finalen — den triggas mitt i grundserien. Egen klubb-pipeline, inte berörd.
  • R3 PhaseMark / SpectatorMark — befintliga. Refaktoreras till koreograf-baserat utan att ändra utseende.
